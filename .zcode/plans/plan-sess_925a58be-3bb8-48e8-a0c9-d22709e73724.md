## 结论

Termux 上跑这套东西**不需要大改**。后端 7 个生产依赖全是纯 JS，零 C 编译；lockfile 里已经记了 `@esbuild/android-arm64` 和 `@rollup/rollup-android-arm64`，所以手机上 `pnpm install --frozen-lockfile` + `pnpm run build` 能直接过。

真正卡住的只有 4 处，都是小改动。剩下的工作量全在「写一套 Termux 的启动/服务脚本」，因为 Termux 没有 Docker、没有 systemd。

---

## 一、要改的文件（4 处）

**1. `backend/package.json:7` 的 `"node": ">=24 <25"` 放宽到 `">=22"`**

这是唯一的硬阻塞。pnpm 对**项目自己**的 `engines` 是硬失败，`--engine-strict=false` 也救不回来。Termux 的 `pkg install nodejs` 给什么版本不由你定（nodejs-lts 是 22 就直接装不上）。

放宽是安全的：我扫了 `backend/` 全部 49 个源文件，`node:sqlite`、`import.meta.dirname`、`Array.fromAsync`、`Object.groupBy`、`util.styleText` 等 Node 24 专属 API **零命中**；实际用到的最高特性是顶层 await 和全局 fetch（Node 18 起）。整个生产依赖闭包里最高的 engine 底线是 Node 20（find-my-way / thread-stream）。`>=24 <25` 是策略声明，不是技术要求。

**2. `scripts/local-static-server.cjs` 补 MIME 类型 + 修路径穿越**

MIME 表里没有 `.wasm` / `.webmanifest` / `.task` / `.moc3` / `.woff2`，`dist/` 里 8 个文件会落到 `application/octet-stream`：`manifest.webmanifest` 这样发出去浏览器可能拒收 PWA manifest（丢掉安装能力），两个 11MB 的 MediaPipe `.wasm` 也会让 `WebAssembly.instantiateStreaming` 失败。

顺手修第 26 行的 `fullPath.startsWith(root)`——那是字符串前缀而不是边界检查，`/%2e%2e/dist2/x` 能逃到同级的 `dist*` 目录。默认绑 127.0.0.1 时无所谓，但你以后可能会设 `HOST=0.0.0.0`。

**3. 根 `.gitignore` 补 `.env` 和 `.env.production`**

现在根 `.gitignore` 完全没有 `.env` 规则（只有第 14 行的 `*.local` 顺带盖住了 `.env.local`）。不能写成 `.env*`——那会把 `.env.capacitor` 也排除掉，而它是 capacitor 构建要用的、里面只有公开的 `VITE_*` 值。`backend/.gitignore` 已经正确排除了 `backend/.env`、`data/`、`backups/`，不用动。

**4.（条件性）`backend/migrations/001_initial.sql:1` 的 `CREATE EXTENSION pgcrypto`**

只在 Termux 的 postgresql 包**没带 pgcrypto** 时才改——这点我在 PC 上查不出来，得在手机上试。

如果确实没有：整个 schema 只从 pgcrypto 用了 `gen_random_uuid()`，而它在 **PostgreSQL 13+ 是内核函数**，所以删掉那一行就行（我 grep 过 `digest(` / `hmac(` / `crypt(` / `pgp_`，migrations 和 `src/` 里全部零命中，哈希都走 Node 的 `createHash`）。

代价要说清楚：`src/migrate.ts:38-41` 会对「已应用后又被改过」的迁移抛错。手机是全新库所以没事，但改完之后 **PC 上导出的数据库 dump 就没法直接恢复到手机**了（dump 里的 `schema_migrations` 存的是旧 checksum）。你要迁数据的话走前端的「完整同步」，别走 pg dump——这也是我上次建议的路子。

顺带一个事实纠正：schema 的真实版本底线是 **PostgreSQL 10**（唯一约束是 `001_initial.sql:33` 的 identity 列），`compose.yaml` 里钉的 `postgres:17-alpine` 是部署选择而不是需求。Termux 给什么版本基本都够。

## 二、要新增的文件（Termux 部署包）

后端现在完全靠 Docker Compose 编排：`.env` 只是给 Compose 做 `${VAR}` 插值用的，**应用本身根本不读 `.env`**（`config.ts:35` 就一句 `envSchema.parse(process.env)`，没有 dotenv）。而 `DATABASE_URL` / `HOST` / `PORT` 是在 `compose.yaml:36-38` 里设的。没了 Compose，这些全都落空。

所以新增 `deploy/termux/`：

| 文件 | 作用 |
|---|---|
| `README.md` | 完整 runbook，含每步的验证点 |
| `setup.sh` | 一次性：`pkg install` → `initdb` → `createdb` → 生成 `.env` → 建库跑迁移 |
| `env.example` | 手机版环境模板：`PORT=43210`、`DATABASE_URL` 走 5432 或 Unix socket、`BACKUP_DIR` 用**绝对路径** |
| `start.sh` / `stop.sh` | 三个进程（api / worker / 静态服务器）的起停，用 `node --env-file=.env` 喂环境变量（零代码改动） |
| `services/` | `termux-services`(runit) 的三份 `run` 脚本，配合 `termux-wake-lock` + `termux-boot` 做开机自启和防 Doze |
| `backup-db.sh` | 直接调 `pg_dump` 的原生备份，替代 `backend/scripts/backup-database.sh`（那 6 个 .sh 全是 Docker/VPS 专用，而且 `#!/usr/bin/env bash` 在非 root Android 上没有 `/usr/bin/env`，只能 `bash xxx.sh` 显式调） |

关键环境值（都是配置，不是代码）：

- `DATABASE_URL` 端口 **5432**，不是 54329——54329 只是 Compose 的宿主映射
- `PORT=43210`，这样前端 `BackendSettings.tsx:347` 里的占位符 `http://127.0.0.1:43210` 一字不用改
- `HOST` 保持 `127.0.0.1`（Compose 里改成 `0.0.0.0` 是容器不得不这么做，你不需要，而且暴露出去只有一个静态 bearer token 挡着）
- `APP_TOKEN` 随机 ≥12 位；`MODEL_VAULT_KEY` 单独生成，别让它默认继承 `APP_TOKEN`（否则以后轮换 token 会让库里的模型密钥解不开）
- `HEARTBEAT_POLL_MS` 从 30 秒调高到 120 秒以上——手机上这是电量决定，不是正确性决定

## 三、手机上的命令（runbook 预览）

```bash
pkg update && pkg install nodejs git postgresql
npm i -g pnpm
termux-wake-lock                      # 不加这句 Doze 会挂掉心跳进程

git clone <你的私有仓库> sullyos       # 注意：别 clone 到 /sdcard，那里没有 exec 权限
cd sullyos

# 数据库
initdb "$PREFIX/var/lib/postgresql"
pg_ctl -D "$PREFIX/var/lib/postgresql" -l "$PREFIX/var/log/pg.log" start
createdb sullyos

# 后端
cd backend && pnpm install
cp ../deploy/termux/env.example .env   # 填 APP_TOKEN / 模型三件套
pnpm build && node --env-file=.env dist/migrate.js
node --env-file=.env dist/api.js &

# 前端（在手机上现场构建）
cd .. && pnpm install
NODE_OPTIONS=--max-old-space-size=3072 pnpm run build
node scripts/local-static-server.cjs dist &
```

浏览器开 `http://127.0.0.1:4173`，设置 →「SullyOS 自主后端」填 `http://127.0.0.1:43210`。

`127.0.0.1` 是安全上下文，所以 **Service Worker、Web Push、`crypto.subtle`、摄像头全部可用**——这正是选 Termux 而不是 Android 内置 Linux 终端的原因（后者有独立网络命名空间，浏览器只能走虚拟网卡 IP，那不是安全上下文，这四样全丢）。

迁移用 `node dist/migrate.js` 而不是 `pnpm db:migrate`，这样连 tsx/esbuild 都不需要（Compose 里 `command: ["node","dist/migrate.js"]` 也是这么做的）。

手机构建的资源账要有数：`node_modules` 363MB + `dist` 57MB + pnpm store，另外 Rollup 要把 75 个 chunk 的模块图全放进 Node 堆——**2GB 可用内存有 OOM 风险，4GB 应该够**，所以上面预置了 `--max-old-space-size`。

## 五、明确不做的

- **不本地化 Tailwind / KaTeX / Google Fonts。** 你选了「手机有网就行」。但要知道 `index.html:30` 的 `cdn.tailwindcss.com` 是**整个应用样式的唯一来源**（仓库里没有 tailwind.config，也没有 PostCSS 步骤），它拉不到 = 完全无样式的裸 HTML。而 Service Worker 里**没有 fetch handler、没有用 Cache API**，一点缓存兜底都没有。所以断网时 UI 是会塌的——这是已知取舍，不是 bug。
- **不补 `public/vendor/live2dcubismcore.min.js`。** `utils/live2dCore.ts:51-60` 已经在探这个路径，但目录不存在，所以现在总是回落到 `cubism.live2d.com`。有网就没问题；补它要下载 Live2D 官方 SDK 文件、涉及第三方许可，我不替你决定。
- **不动 `worker.ts:38` 的 `timer.unref()`。** 只是标注：万一首次 tick 没能建立任何数据库连接、连接池里没有活跃句柄，unref 的定时器会让进程静默退出而不是重试。读代码看出来的，没有实测。
- **不动 `backupRepo.ts:335-336`。** `purgeBackupRepo` 是先 `fs.rm` 整棵树再 `git init`，git 缺失时会「先删干净再报 500」。你要 clone 就必然装了 git，所以这条不会触发。
- **不改那 6 个 `backend/scripts/*.sh`。** 它们是 Docker/VPS 专用，不是「适配」能救的，直接用 `deploy/termux/` 里的原生替代品。
- 安全项照旧全部保持原样（videoParser 的 key、proactivePushConfig 的 token、BrowserApp 的 HTML 注入、TTS 中继、cleartext）。

另外一个与手机无关但你该知道的：`/api/minimax/*`、`/api/fishaudio/tts`、`/api/elevenlabs/tts` 这三个代理只存在于 `vite.config.ts` 的 `server:` 块里，也就是**只有 dev server 有**。任何静态 `dist/` 部署下这些路径都会被 SPA fallback 返回 `index.html`（HTTP 200 + text/html），依赖同源代理的 TTS 在任何系统上都不通——你现在 PC 上跑 `pnpm preview` 也是这样。要用就得在设置里填直连的 TTS 地址。
